# 🐾 TamaBot — полная документация

Стек: **Python 3.12 · aiogram 3.x (long polling) · MySQL 8 · SQLAlchemy 2 async ·
APScheduler · loguru · Textual 8 (TamaConsole)**.
Redis опционален (на Windows — Memurai); без него работает in-memory fallback для
кулдаунов/FSM. Бот полностью русскоязычный (RU-only), весь интерактив — только в ЛС.

---

## 1. Возможности бота

### 1.1 Доступ и приватность

* **Только личные сообщения.** Гейт-мидлвар `AccessGateMiddleware`
  (`app/middlewares/gate.py`, outer-middleware на все апдейты) молча игнорирует любые
  Message/CallbackQuery из групп и каналов: бот ничего туда не пишет, не отвечает на
  команды, не редактирует чужие сообщения. В диспетчер пропускаются только безмолвные
  служебные сценарии: трекер активности и регистрация новых участников канала с
  последующим приветствием в ЛС.
* **Проверка подписки на канал.** Для всех взаимодействий (кроме входных команд
  `/start` и `/help`) пользователь должен быть подписан на канал `CHANNEL_USERNAME`:
  проверка через `getChatMember`, кэш результата ~5 минут (Redis + in-memory
  fallback). При недоступности API действует fail-open. Неподписанным вместо ответа —
  заглушка «🔒 Бот доступен только подписчикам канала» с url-кнопкой «📢 Подписаться:
  t.me/<channel>» и кнопкой «✅ Я подписался — проверить» (`gate:check`).
* **Приветствие новичков канала.** Три сигнала ведут в один пайплайн
  (`add_pending_subscriber` → `welcome_pending_subscribers`, ровно одно DM-приветствие
  благодаря колонке `welcomed_at` в таблице `channel_subscribers`).
  Сброс отметки (второе приветствие) возможен только по реальному событию
  вступления в ДРУГОЙ отслеживаемый чат (`reset_welcome=True`); косвенные
  сигналы — `/start`, первое сообщение в чате — повторных приветствий не
  вызывают (фикс двойного DM в v1.5.7):
  ① событие `chat_member` канала (бот — админ с правом *Manage users*, `"chat_member"`
  добавлен в `allowed_updates`);
  ② первое сообщение пользователя в отслеживаемом чате;
  ③ фоновый скан `scan_channel_members` (APScheduler, `CHANNEL_SCAN_MINUTES`,
  Redis-lock) — сверка счётчика участников и доприветление «зависших» pending.
  Тексты: `WELCOME_CHANNEL_ENABLED`, `CHANNEL_WELCOME_TEXT` ({name}, {channel}).
* **v1.5.13/1.5.14 — фикс запуска на Windows.** Импорт конфига падал при
  чтении `.env`: `TypeError` (python-dotenv новых версий не принимает
  файловый объект) и `UnicodeDecodeError` (UTF-8-файл с кириллицей в системной
  cp1251). Теперь `.env` читается собственным парсером с автоподбором
  кодировки (utf-8-sig → cp1251 → latin-1), нормализацией CRLF/BOM; битый
  файл больше не роняет бот. Короткие ключи `API_ID/API_HASH/PHONE` из
  `.env` подхватываются как `TELEGRAM_*`.
* **v1.5.12 — полная поддержка Telegram API (MTProto / Telethon).** Bot API
  не отдаёт список участников канала, поэтому подписчики «до запуска бота»
  в welcome-очередь не попадали. Теперь при заданных ключах всё работает
  автоматически:
  - `MTPROTO_AUTOSYNC=true` (дефолт) — при старте бот тянет ЦЕЛИКОМ список
    участников обязательных чатов через user-аккаунт (`get_full_channel`) и
    ставит их в welcome-очередь; дальше дельта каждые `MTPROTO_SYNC_MINUTES`
    минут (по умолчанию 60);
  - PK `channel_subscribers` — пара `(user_id, chat_id)`: MTProto-sync не
    создаёт «новых» из уже известных, приветствие по-прежнему ровно одно DM
    на пользователя (дедупликация `welcomed_at` + `welcome_sent_chat_id`);
  - `python -m app.services.mtproto_sync --login` — интерактивный логин
    (код/2FA), печатает `MTPROTO_SESSION_STRING` для безинтерактивного
    деплоя; `--first-run` — принудительно полная синхронизация из CLI;
  - админ-команды: `/mtproto` (статус настройки, без показа секретов),
    `/syncnow [full|delta]` — немедленная синхронизация + flush приветствий;
  - `MTPROTO_ANSWER_MODE=user|hybrid` — UserBot «присутствует» в отслеживаемых
    чатах от user-аккаунта (реакции на стикеры/мемы; игровая логика, гейт и
    команды остаются на основном боте; антифлуд 1 сообщение / 3 сек).
  Ключи `API_ID/API_HASH/PHONE/TELEGRAM_PASSWORD/MTPROTO_SESSION_STRING`
  читаются из `.env` в любом формате имён (с префиксом TELEGRAM_ и без);
  пример с фейковыми значениями — в `.env.example`. С user-аккаунта НИЧЕГО
  не рассылается; приветствия шлёт основной бот через Bot API.

### 1.3 Питомец (тамагочи) — `app/services/tamagotchi.py`

* Шкалы hunger/happiness/energy/hygiene с деградацией во времени (фоновая decay-задача
  по расписанию), XP/уровень, монеты, статы strength/agility/intellect.
* Виды: 🐱 Котёнок (0), 🐶 Щенок (150), 🦊 Лисёнок (250), 🦉 Совёнок (350),
  🐉 Дракончик (800) — уникальные множители деградации, стартовые статы, предпочтения
  действий, бонусы (xp_mult/coin_mult/play_happy/sleep_bonus).
* Действия: кормёжка (из инвентаря), мытьё, сон, тренировки, прогулки (случайные
  события/находки), история ухаживаний.
* Критическое состояние → реанимация за монеты (`revive_cost`), однократный бесплатный
  revive для новичков, либо усыновление нового.
* Кастомизация: цвета (golden/shadow/candy/aurora) и аксессуары (🎩🎀🕶️👑🧣) за монеты;
  сезонная модификация деградации (`WEATHER_ENABLED`).

### 1.4 Экономика: магазин и инвентарь — `app/handlers/shop.py`

Монеты начисляются за засчитанные сообщения (кулдаун + антифрод-лимиты), победы в
играх/дуэлях, награды за достижения и рефералку. Товары (`ITEMS_SEED`): еда (Хлеб,
Яблоко, Стейк, Тортик), игрушки (Мячик, Лазерная указка), медицина (Лекарство,
Витамины). Покупка → инвентарь → применение к питомцу одним тапом.

### 1.5 Мерч канала — `app/handlers/merch.py`

Отдельный раздел (не связан с питомцем), флаг `MERCH_ENABLED`. Категории: футболки,
худи, аксессуары. Витрина задаётся `MERCH_ITEMS` («Категория|Название|Цена₽|Описание|Размеры;…»),
внешний магазин — кнопка «🌐 Открыть» (`MERCH_URL`).

### 1.6 Мини-игры — `app/handlers/games.py`

✊✋✌️ Камень-ножницы-бумага против питомца; ⚡ «Реакция» (успеть нажать быстрее всех);
❓ «Угадайка» (число/символ с подсказками). Тратят энергию питомца, дают монеты/XP,
прогресс в ачивках игр.

### 1.7 Арена и социалка — `app/services/pet_duels.py`, `pet_social.py`

Еженедельная лига дуэлей питомцев: подбор соперника по силе, бой по статам, кулдаун
после поражения, недельный топ и награждение победителей (`weekly_arena_finish`,
команда `/award`). Питомцы заводят друзей (`pet:friends`), вместе гуляют.

### 1.8 Достижения, статистика, топы, карточка

* `app/services/achievements.py`: каталог `ACHIEVEMENTS` по категориям
  (Активность, Стрики, Реакции, Питомец, …) с редкостями common/rare/epic/legendary,
  условиями (messages_total, streak_days, reactions_* и т.д.) и наградами coins+XP;
  автоанлок при событиях + уведомление в ЛС.
* `app/handlers/stats.py`: личная статистика с разбивкой; топы — периоды
  📅 День / 🗓 Неделя / ♾ Всё время × номинации 👑 Общий, 💬 Болтуны, 💖 Реакции,
  🎭 Эмоциональные, 💚 Добряки, 🔥 Серии, 🐾 Питомцы, ⭐ Уровни.
* `app/services/profile_card.py`: PNG-карточка профиля (Pillow), кеширование по хешу контента.

### 1.9 Трекер активности — `app/handlers/tracker.py`

Считает в отслеживаемых чатах (`TRACKED_CHAT_IDS`, пусто = все чаты бота кроме ЛС):
сообщения (минимальная длина, кулдаун, XP/монеты), реакции (лимит в сутки на пару
A→B, «эмоциональность»/«добряк»), стрики дней активности. Работает **безмолвно** —
ничего не публикует в чаты.

### 1.10 Фоновые задачи — `app/tasks/scheduler.py` (APScheduler)

| Задача | Расписание | Действие |
|---|---|---|
| decay_all_pets | каждые N мин | деградация шкал питомцев |
| flush_notifications | по таймерам | напоминания «питомец скучает», утренние/вечерние |
| check_streak_expiry | 00:15 | сброс просроченных стриков |
| daily_reports | `DAILY_REPORT_HOUR_UTC` | ежедневный отчёт в ЛС |
| evening_streak_warnings | `EVENING_REMINDER_HOUR_UTC` | «стрик под угрозой» |
| weekly_leaderboard | пн 00:30 | итоги недели топов |
| weekly_arena_finish | пн 00:40 | финал арены, призы |
| scan_channel_members | `CHANNEL_SCAN_MINUTES` | сверка участников канала, доприветствия |

Все уведомления приходят только в ЛС и отключаются тумблерами «⚙️ Уведомления»:
🐾 Питомец скучает, 🔥 Стрик под угрозой, 🏆 Достижения, 🌅 Ежедневный отчёт.

### 1.11 Рефералка

Реферальная ссылка ведёт на канал: `https://t.me/<CHANNEL_USERNAME>?start=invite_<tg_id>`.
Приглашённый фиксируется в БД, пригласивший получает `INVITE_REWARD_COINS` монет.

### 1.12 Команды (работают только в ЛС)

`/start` — главное меню · `/help` — справка · `/pet` — хаб питомца · `/stats` —
статистика · `/top` — топы · `/ach` — достижения · `/card` — PNG-карточка ·
`/settings` — уведомления · `/arena` — арена · `/award` — итоги прошлой недели арены.

## 2. Установка на Windows Server

### 2.1 Python
1. Установить **Python 3.12.x** (галочка *Add python.exe to PATH*).
2. Проверка: `python --version`.

### 2.2 MySQL
1. Установить **MySQL Community Server 8.x** (https://dev.mysql.com/downloads/installer/),
   сервис автозапуска, порт 3306.
2. Выполнить:
   ```sql
   CREATE DATABASE tamabot CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;  -- ВАЖНО: utf8mb4 (эмодзи)
   CREATE USER 'tamabot'@'localhost' IDENTIFIED BY 'СИЛЬНЫЙ_ПАРОЛЬ';
   GRANT ALL PRIVILEGES ON tamabot.* TO 'tamabot'@'localhost';
   FLUSH PRIVILEGES;
   ```

### 2.3 Redis (опционально, но рекомендуется)
- **Memurai Developer** (бесплатно, https://memurai.dev) — ставится как сервис Windows.
- Без Redis бот запустится, но кулдауны/FSM будут сбрасываться при рестарте.

### 2.4 Зависимости проекта
```bat
install.bat
```
Создаёт `venv`, ставит `bot/requirements.txt`, создаёт `.env` из `.env.example`
и открывает его в блокноте.

### 2.5 Настройка Telegram
1. @BotFather → `/newbot`, получить токен → `BOT_TOKEN`.
2. Отключить privacy mode НЕ нужно: в группах бот всё равно молчит, для реакций
   достаточно состоять в чату.
3. Создать **канал**, добавить бота **администратором с правом Manage users**
   (для событий `chat_member` и проверки подписки). Бот не будет ничего публиковать
   в канал.
4. Привязать к каналу **группу обсуждения**, добавить туда бота (трекер активности).
5. Узнать ID канала/группы (переслать сообщение из группы @userinfobot или посмотреть
   логи бота) → `TRACKED_CHAT_IDS`, `CHANNEL_CHAT_ID`; юзернейм канала → `CHANNEL_USERNAME`.
6. Командное меню: @BotFather → `/setcommands`:
   `start, help, pet, stats, top, ach, card, settings, arena, award`.

## 4. Запуск и эксплуатация

### 4.1 run.bat — запуск бота
```bat
run.bat
```
Long polling с живыми цветными логами (loguru → консоль + `bot/logs/`). Ctrl+C —
graceful shutdown (остановка scheduler, закрытие Redis/engine).

### 4.2 console.bat — TamaConsole (Textual)
```bat
console.bat          :: эквивалент: cd bot && venv\Scripts\python -m app.console
```
Полноэкранное управление без второго окна:

* **📋 Логи** — живой лог с фильтрами и подсветкой уровней;
* **📊 Дашборд** — аптайм, пользователи/питомцы/сообщения, графики активности;
* **🗄 БД** — просмотр таблиц и запросы;
* **⚙️ Настройки** — редактирование `.env` прямо из UI (валидация ключей);
* **🔍 Пользователи** — поиск по нику/ID, карточки;
* hotkey `r` — Пуск/Стоп бота из консоли (запуск отдельным процессом, перехват логов).

### 4.3 Кодировка BAT-скриптов
`install.bat`, `run.bat`, `console.bat` сохранены в **cp1251 (ANSI Russian) с CRLF** —
требование `cmd.exe`. При редактировании сохранять в cp1251/«Кириллица Windows»
(Notepad++ → Кодировки → Кириллица → Windows-1251), иначе cmd перестанет понимать скрипты.

### 4.4 Автозапуск (сервис)
Рекомендуется NSSM / Task Scheduler: запуск `run.bat` при старте ОС, restart on failure.
Логи ротятся в `bot/logs/`.
